# 暗魂（darksoul）

- 显示名：darksoul
- 作者：[zx070326-hash](https://github.com/zx070326-hash)。代码由 Claude（Anthropic 的 AI 模型）在作者指导下编写和迭代。
- 文件：`bot.js`，单文件，约 5.7 万字符，只依赖 `lab` 接口。

导入：

```powershell
node --import tsx scripts/import-bot.ts bots/darksoul/bot.js 'darksoul'
```

## 策略

对局中的输入只有 `lab.observe()`、`lab.act()` 和 `lab.fire()` 返回的 JPEG，输出只有移动、旋转、瞄准和单发请求。

### 感知

- 脚本自带基线 JPEG 局部解码器。熵码顺序读完，反变换只做三类单元：两车周围、HUD 血条和热量条，以及亮度直流相对背景突增的单元（弹丸）。一帧解码加识别约 2.7 毫秒。
- 车心先由车体暗色像素求质心，再用四块装甲逐板求质心精修。装甲是亚像素绘制的，所以精修后车心误差约 0.05 像素。
- 装甲相位用四倍角圆均值求出。炮管朝向取外环高亮像素的众数方向。
- 弹丸归属和方向由拖尾颜色判定。

### 时间

- 供图按固定周期采样，脚本用帧号把每帧映射回采样时刻。
- 自己的随机横移有大量拐点，脚本把拐点在画面中出现的时刻与指令生效时刻对齐，在线校准画面与指令之间的时间偏移，同时标定自身速度（房间功率可调）。
- 看到自己的新弹丸时，用它离出膛点的距离反推出膛延迟。
- `act` 返回时如果还是旧帧，就在下一个控制边界之前用 `observe` 取刚编码好的新帧。这样决策能赶上下一个边界生效，信息时延少一个控制周期。实测中，这一项对攻防两端的提升都最大。

### 瞄准

- 持续统计对手「当时按匀速外推，若干时长后实际偏差多少」，误差记在对手当时的速度坐标系下，并按预测时长和距上次变向的时长分桶。
- 这些误差不假设匀速，也不假设高斯分布，能学到「速度并不保持」一类的行为。
- 对每个横向落点，用预先算好的装甲命中表（横向偏移 × 装甲相对相位）在样本分布上求命中概率，取最大者。

### 开火

- 只在 140 像素以内、预测时域（画面时延加飞行时间）足够短时开火。
- 平时炮口对准对手车心作诱饵。对手如果按炮线摆装甲相位，就会把车体正对我方炮线。
- 决定开火时才甩到最佳落点，等炮塔到位立即单发，并让甩炮在供图采样边界生效，对手要到下一帧才看得到。
- 开火前再按实际炮塔方向复核命中概率。

### 防御

- 每个控制周期在 16 个平移方向（必要时加旋转）里，选「来弹与对手炮线威胁 + 贴墙 + 距离 + 随机游走方向」代价最低的一个。
- 来弹威胁由逐步推进的装甲/车体几何判定，用来决定躲开，或转到让来弹打在车体上的相位。
- 随机横移在采样边界处改向，对手拿到的最新画面里的速度总是过时的。

### 热量

热量用 HUD 读数加上最近请求数估计，打完这一发后不超过 92，任何情况下都不过热。

## 预期行为

- 准备阶段炮塔指向对手。开局后逼近到约 90 像素，不在远处浪费热量。
- 近身后车体保持装甲斜对对手炮线，持续小幅随机横移，择机甩炮单发。
- 对局结束后接口调用开始失败，脚本自行退出。
- 不读写文件、不联网、不创建子进程或 Worker。满 60 秒的对局调用约 6000 次（宿主上限 30000）。

## 已知局限

- 没有在 DSH Desktop 界面和 Deno 受限运行时里实际跑过。代码只用了标准 JavaScript 和 `performance.now()`。
- 依赖对帧时序的估计。机器负载很高时（本地同时跑 12 局），表现会明显下降。
- 主动取帧会在两次控制边界之间忙等几毫秒，会占用一个 CPU 核心的一部分。
- 画面宽度明显小于 960 时，弹丸识别会变差，主要影响躲弹。
